# Deploy guide (Render + Vercel + Atlas)

Total time: about 15 minutes. The order matters: deploy the API first, because the frontend needs its URL baked in at build time.

## 0. Atlas (done)
- Cluster: AWS Mumbai (ap-south-1). Network Access includes `0.0.0.0/0`.
- Connection string format: `mongodb+srv://<user>:<password>@cluster0.v6elg4f.mongodb.net/hack4hack?retryWrites=true&w=majority`

## 1. API on Render
1. render.com → **New → Blueprint**, then pick the GitHub repo `Hack4Hack-Entry`. Render reads `render.yaml`.
   - Or do it manually: **New → Web Service** and set:
     - Root Directory `server`
     - Build `npm ci --omit=dev`
     - Start `npm start`
     - Region **Singapore**
     - Health check `/health`
2. Environment variables:
   | Key | Value |
   |---|---|
   | `MONGODB_URI` | the Atlas string above (with the real password) |
   | `JWT_SECRET` | auto-generated by the Blueprint, or any long random string |
   | `CLIENT_ORIGIN` | leave as `http://localhost:5173` for now; updated in step 3 |
   | `NODE_VERSION` | `22` |
3. Deploy. Then check `https://<api>.onrender.com/health`, which should return `{"ok":true}`.

## 2. Frontend on Vercel
1. vercel.com → **Add New → Project**, then import `Hack4Hack-Entry`.
2. Settings:
   - **Root Directory:** `client`
   - Framework: Vite
   - Build `npm run build`
   - Output `dist`
3. Environment variable: `VITE_API_URL` = `https://<api>.onrender.com` (no trailing slash).
4. Deploy. `client/vercel.json` already rewrites deep links such as `/teams/123` to `index.html`.

## 3. Connect them
- In Render, set `CLIENT_ORIGIN` = `https://<app>.vercel.app,http://localhost:5173`, then save. The service redeploys.

## 4. Verify
- Open the Vercel URL and log in as `demo1@hack4hack.dev` / `password123`.
- Check that the green "live" dot appears in the header, which means the WebSocket connected.
- Run the deployed load test from your laptop:
  ```bash
  cd server
  TARGET=https://<api>.onrender.com npm run loadtest
  ```
  Then add the numbers to `docs/LOADTEST.md` (section C).

## Notes
- **Free Render instances sleep after about 15 min idle.** The first request after that takes around 30–50 s while it wakes up. Before a demo or review, open `/health` once to wake it.
- `npm run seed` wipes the database. Never run it against Atlas after reviewers start using the app.
